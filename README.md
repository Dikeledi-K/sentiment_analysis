# Quality & Returns Intelligence

A beginner-friendly Streamlit application for turning customer product feedback and returns data into quality signals. It combines sentiment classification, transparent keyword-based issue categories, product-level review flags, and return metrics in one local dashboard.

The project is intended for learning, exploration, and portfolio demonstration. Its included data is synthetic; it is not a live returns system or proof that a product is defective.

## Project overview

Quality & Returns Intelligence helps an analyst explore:

- How customer feedback is distributed across positive, neutral, and negative sentiment
- Which product issue themes appear in the feedback, such as damaged shipments, faulty components, missing parts, and durability problems
- Which products have recurring negative feedback or issue reports that may warrant investigation
- How many records are marked as returned and, when unit totals are available, the return rate
- How reported return cases change over time when usable dates and return statuses are provided

The platform is a decision-support tool. Model predictions and keyword categories should be checked by a human analyst before operational action.

## Features

- Analyse one feedback comment for sentiment, model confidence, and a likely issue category
- Upload a CSV or run the included product-quality demo dataset
- Explore sentiment counts, a product-by-issue heatmap, return trends, and products flagged for review
- Filter and search analysed feedback
- Download analysed data as CSV and quality insights as Markdown
- Review model metrics generated by the training pipeline

## Requirements and installation

Use Python 3.11 or newer. From the project directory, create and activate a virtual environment, then install the requirements.

### Windows PowerShell

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

If PowerShell blocks virtual-environment activation, use the environment's Python executable directly, for example:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

### macOS or Linux

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

## Run the application

From the project root:

```bash
python -m streamlit run app.py
```

Open the local URL printed by Streamlit, usually `http://localhost:8501`.

### Dashboard workflow

1. Open **Dataset** in the top navigation.
2. Click **Analyze built-in demo dataset**, or upload a CSV file.
3. For an uploaded file, choose the text column and any available product, category, and date columns, then click **Run analysis**.
4. Open **Quality** to review the executive metrics, issue heatmap, return trend, and products to investigate.
5. Open **Reports** to download the Markdown report. The analysed records can also be downloaded as a CSV from Dataset.

Uploading a file does not start analysis automatically; click the analysis button after choosing the columns. The analysis is retained in the current Streamlit session.

## CSV data guide

### Uploading feedback for analysis

Only a text column containing customer feedback is required. During upload, select that column in the app. Product, category, and date columns are optional, but they enable product comparisons and time-series views.

For additional dashboard metrics, include these columns when available:

| Column | Purpose |
| --- | --- |
| `text` or another selected text field | Customer feedback used for sentiment and issue classification |
| `product_name` or another selected product field | Groups feedback for the issue heatmap and product review flags |
| `category` or another selected category field | Retained for category-level analysis and reporting |
| `date` or another selected date field | Enables monthly trend charts; invalid dates are ignored |
| `return_status` | Rows marked `returned`, `refunded`, or `return complete` count as reported return cases |
| `units_sold` | Numeric sales volume used for the unit return-rate calculation |
| `units_returned` | Numeric returned-unit volume used for the unit return-rate calculation |

The unit return rate is calculated as returned units divided by sold units. When a product field is selected, the dashboard uses one unit-total record per product to avoid counting repeated product totals multiple times. Monthly return trends count dated records marked as returned; they are not a unit return rate.

### Retraining the sentiment model

Training data must have a `text` column and a `sentiment` label column. Sentiment labels should be `positive`, `neutral`, or `negative`. The demo file already has these fields.

## Model and analysis approach

The sentiment pipeline uses text cleaning, TF-IDF features with unigrams and bigrams, and a class-balanced logistic regression classifier. It reports accuracy, macro precision, macro recall, macro F1, a classification report, and a confusion matrix.

Issue categories are assigned by transparent keyword rules in `src/issue_classifier.py`; this is not a trained defect-diagnosis model. Product review flags use minimum record counts and thresholds for negative sentiment or non-`Other` issue signals. These are triage indicators, not causal conclusions.

## Train the model

Train with the included labelled demo dataset:

```bash
python train_model.py
```

The command writes the model to `models/sentiment_model.joblib` and evaluation metrics to `reports/model_metrics.json`. Custom paths can be supplied with `--data`, `--model`, and `--metrics`, for example:

```bash
python train_model.py --data data/my_labelled_reviews.csv --model models/custom_model.joblib --metrics reports/custom_metrics.json
```

## Responsible use and limitations

- The included data is synthetic demonstration data and should not be presented as real customer or operational results.
- Sentiment models can misread sarcasm, slang, spelling variation, mixed feedback, or short comments.
- Keyword rules can miss subtle issues and may match terms without understanding full context.
- Return rates are only meaningful when the uploaded unit totals are accurate and consistently defined.
- A flagged product is a prompt for investigation, not evidence of a manufacturing defect or supplier fault.
- Remove personal and sensitive information before uploading customer data, and follow applicable privacy requirements.
- Have qualified people validate findings before making warranty, returns, supplier, or manufacturing decisions.
