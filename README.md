# Quality & Returns Intelligence

A beginner-friendly Streamlit application for turning customer product feedback and returns data into quality signals. It combines sentiment classification, transparent keyword-based issue categories, product-level review flags, and return metrics in one local dashboard.

The project is intended for learning, exploration, and portfolio demonstration. Its included data is synthetic; it is not a live returns system or proof that a product is defective.

## Project overview

Quality & Returns Intelligence helps an analyst explore:

- How customer feedback is distributed across positive, neutral, and negative sentiment
- Which product issue themes appear in the feedback, such as damaged shipments, faulty components, missing parts, and durability problems
- Which products have recurring negative feedback or issue reports that may warrant investigation
- How many records are marked as returned and, when unit totals are available, the return rate
- How reported return cases change over time when usable dates and return statuses are provided

The platform is a decision-support tool. Model predictions and keyword categories should be checked by a human analyst before operational action.

## Features

- Analyse one feedback comment for sentiment, model confidence, and a likely issue category
- Upload a CSV or run the included product-quality demo dataset; text, product, category, and date columns are detected automatically from their names
- Explore sentiment counts, a product-by-issue heatmap, return trends, and products flagged for review with the reason they were flagged
- Filter and search analysed feedback
- Download analysed data as CSV and quality insights as Markdown
- Review model metrics generated by the training pipeline

## Requirements and installation

Use Python 3.11 or newer. From the project directory, create and activate a virtual environment, then install the requirements.

### Windows PowerShell

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

If PowerShell blocks virtual-environment activation, use the environment's Python executable directly, for example:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

### macOS or Linux

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

## Run the application

From the project root:

```bash
python -m streamlit run app.py
```

Open the local URL printed by Streamlit, usually `http://localhost:8501`.

The trained model file is not stored in the repository. On the first run, if `models/sentiment_model.joblib` does not exist, the app trains it from `data/training_reviews.csv`, which takes a few seconds.

### Analysing a dataset

1. Open **1 · Load data**.
2. Click **▶ Analyze built-in demo dataset**, or drop a CSV into **Upload your own CSV**.
3. For an uploaded file, check the dropdowns under **Map the columns**. They are pre-selected from the column names (see the table below). Make sure **Product name column** points at the product, not at a field such as `return_reason`.
4. Click **Run analysis**. A **Current analysis** panel appears with record counts, a preview, and **Download analysed CSV**.
5. Click **Next: review quality →** to open the dashboard.
6. Click **Next: build the report →** to preview and download the Markdown report.

Uploading a file does not start the analysis; click **Run analysis** after checking the columns. Results stay available while the browser session is open. **Clear analysis** in the sidebar or on **1 · Load data** removes them.

### Customising the look

Colours and fonts live in two places:

- `.streamlit/config.toml` sets the Streamlit theme: page background, text, accent (`primaryColor`), borders, corner radius, fonts, and the dark sidebar.
- `src/ui.py` mirrors the brand colours for the custom page elements (brand bar, hero, step tracker, cards) and holds the chart colours and the shared chart style (`style_figure`).

To rebrand, change the accent and background colours in both files. Chart colours are separate on purpose. Sentiment uses blue for positive, gray for neutral, and red for negative, a set checked for colour-blind readability. Magnitudes such as heatmaps use a single blue scale. Charts that need a new chart type can reuse `ui.style_figure` and `ui.show_chart` so they match the rest of the dashboard.

## CSV data guide

### Uploading feedback for analysis

Only a column of customer feedback text is required. Product, category, and date columns are optional, but they enable product comparisons and time-series views. Files saved as UTF-8 or from Excel on Windows are both accepted.

The app pre-selects columns with these names (case-insensitive). Any other column can be chosen manually:

| Dropdown | Recognised column names | Used for |
| --- | --- | --- |
| Feedback text | `text`, `review_text`, `customer_feedback`, `feedback`, `comment`, `comments`, `review`, `message` (otherwise the column with the longest text) | Sentiment and issue classification |
| Product name | `product_name`, `product`, `item_name`, `item` | Defect heatmap, product review flags, report |
| Product category | `category`, `product_category`, `item_category` | Category breakdown and flags |
| Date | `date`, `review_date`, `feedback_date`, `order_date`, `created_at` | Monthly trend chart; invalid dates are ignored |

These columns are read automatically when present:

| Column | Purpose |
| --- | --- |
| `return_status` | Rows marked `returned`, `refunded`, or `return complete` count as reported return cases |
| `return_requested`, `returned`, or `is_returned` | Rows with `Yes`, `Y`, `True`, or `1` count as reported return cases |
| `units_sold` | Numeric sales volume used for the unit return rate |
| `units_returned` | Numeric returned units used for the unit return rate |

Rows with empty feedback text are skipped and counted in the completion message. The analysed CSV keeps every original column and adds `predicted_sentiment`, `confidence`, and `issue_category`. If you map a different column to a standard name that already exists in the file, for example `item` as the product while the file also has `product_name`, the original column is kept as `product_name_original`.

The unit return rate is returned units divided by sold units. When a product column is selected, one unit-total record per product is used so repeated product totals are not counted twice. Reported return cases and the monthly return trend count rows marked as returned; they are not a unit return rate. Without `units_sold` and `units_returned`, the dashboard and report show the return rate as "Not provided".

### Retraining the sentiment model

Training data must have a `text` column and a `sentiment` label column. Sentiment labels must be `positive`, `neutral`, or `negative`; other labels are rejected. The default training file is `data/training_reviews.csv`. It is kept separate from the dashboard demo data so the demo shows how the model handles feedback it has not seen.

## Model and analysis approach

The sentiment pipeline uses text cleaning, TF-IDF features with unigrams and bigrams, and a class-balanced logistic regression classifier. It reports accuracy, macro precision, macro recall, macro F1, a classification report, and a confusion matrix on a held-out 25% test split, plus a 5-fold cross-validated macro F1 on the training split. The training set is small (146 synthetic reviews), so treat these scores as rough indicators. The current model scores about 75% on its held-out split and about 92% on the demo dataset, which it was not trained on. Mixed reviews ("good, but…") and complaints that use words missing from the training data are the most common errors.

Issue categories are assigned by transparent keyword rules in `src/issue_classifier.py`; this is not a trained defect-diagnosis model. Keywords match whole words only and categories are checked in order, from specific (missing parts, transit damage) to broad (faulty components, performance). The first match wins. Because the rules do not read sentiment, praise that mentions a component (for example "long battery life") is still tagged with that component's category.

Products are flagged for review when they have at least two records and either 40% or more negative feedback or 40% or more records with a classified issue (anything other than `Other` or `Needs Review`). The flag table states which threshold was crossed. These are triage indicators, not causal conclusions.

## Train the model

Train with the included labelled training dataset:

```bash
python train_model.py
```

The command writes the model to `models/sentiment_model.joblib` and evaluation metrics to `reports/model_metrics.json`. Restart the Streamlit app afterwards so it loads the new model. Retrain after upgrading scikit-learn; a model saved by a different version triggers an `InconsistentVersionWarning` and may give unreliable results. Custom paths can be supplied with `--data`, `--model`, and `--metrics`, for example:

```bash
python train_model.py --data data/my_labelled_reviews.csv --model models/custom_model.joblib --metrics reports/custom_metrics.json
```

## Responsible use and limitations

- The included data is synthetic demonstration data and should not be presented as real customer or operational results.
- Sentiment models can misread sarcasm, slang, spelling variation, mixed feedback, or short comments.
- Keyword rules can miss subtle issues and may match terms without understanding full context.
- Return rates are only meaningful when the uploaded unit totals are accurate and consistently defined.
- A flagged product is a prompt for investigation, not evidence of a manufacturing defect or supplier fault.
- Remove personal and sensitive information before uploading customer data, and follow applicable privacy requirements.
- Have qualified people validate findings before making warranty, returns, supplier, or manufacturing decisions.
